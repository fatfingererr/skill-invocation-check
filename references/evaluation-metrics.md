# 评测指标定义

<overview>
定义 Description 评测的核心指标及其计算方式。
</overview>

<metrics>
## 核心指标

### 召回率 (Recall)

**定义：** 在所有"应该触发"的测试用例中，实际触发的比例。

**公式：**
```
召回率 = 应触发中实际触发数 / 应触发总数
```

**意义：** 衡量"该用的时候用了没"

**目标：** ≥ 80%

**低召回率表示：**
- Description 缺少关键触发词
- 触发条件写得太保守
- 边界定义太窄

---

### 精确率 (Precision)

**定义：** 在所有"不应该触发"的测试用例中，正确未触发的比例。

**公式：**
```
精确率 = 不应触发中正确未触发数 / 不应触发总数
```

**意义：** 衡量"不该用的时候克制住了没"

**目标：** ≥ 90%

**低精确率表示：**
- Description 太模糊
- 缺少负向触发说明
- 和其他 skill 边界重叠

---

### 混淆矩阵

| | 实际触发 | 实际未触发 |
|---|---|---|
| **应触发** | TP (True Positive) | FN (False Negative) |
| **不应触发** | FP (False Positive) | TN (True Negative) |

- **TP**: 正确触发
- **FN**: 漏触发 (under-triggering)
- **FP**: 误触发 (over-triggering)
- **TN**: 正确未触发
</metrics>

<thresholds>
## 评分标准

| 等级 | 召回率 | 精确率 | 评价 |
|------|--------|--------|------|
| 🟢 优秀 | ≥90% | ≥95% | 可上线 |
| 🟡 良好 | ≥80% | ≥90% | 可接受，建议迭代 |
| 🟠 待改进 | ≥60% | ≥80% | 需要优化 |
| 🔴 不合格 | <60% | <80% | 必须重写 |
</thresholds>

<tradeoffs>
## 权衡取舍

### 召回率 vs 精确率

两者往往存在权衡：
- 放宽触发条件 → 召回率 ↑，精确率 ↓
- 收紧触发条件 → 召回率 ↓，精确率 ↑

### 优先级建议

**大多数情况：优先精确率**
- 误触发浪费 Token 和时间
- 用户体验差（莫名加载不相关 skill）

**特定情况：优先召回率**
- Skill 是关键能力，漏触发代价大
- 用户不太可能用其他方式完成任务
</tradeoffs>

<sample_size>
## 样本量建议

| 评测集规模 | 最小建议 | 理想规模 |
|-----------|---------|---------|
| 应触发用例 | 8 条 | 10-15 条 |
| 不应触发用例 | 8 条 | 10-15 条 |
| **总计** | 16 条 | 20-30 条 |

**注意：**
- 数量太少（<10）统计意义不足
- 数量太多（>50）维护成本高
- 关注覆盖多样性比单纯增加数量更重要
</sample_size>
